# Card Statistics & Insights (Issue #22)

Документация отдельного экрана статистики и вычисления доменных метрик в **KotoKitsu**.

## Архитектура статистики

Статистика рассчитывается чистыми, детерминированными функциями селекторов без прямого взаимодействия с DOM-рендерером и без мутации основного `app_state`.

```text
источник данных (state.srs, state.reviewEvents, state.masteryArchive)
→ getEffectiveReviewEvents (нормализация, фильтрация, исключение undone)
→ статистические селекторы (retention, lapses, workload, forecast, skill, mastery)
→ buildStatisticsViewModel (агрегированная View Model)
→ UI (ui/statistics.js с помощью SVG и CSS)
```

## Определения и таблицы метрик

| Метрика                      | Источник данных                    | Формула                                                                                                       | Исключения                                                                                                                | Минимальный объём                      |
| ---------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| **Observed Retention**       | `state.reviewEvents`               | `успешные первые попытки (Hard/Good/Easy) / все первые попытки`                                               | Undone события, внутрисессионные retries, supplemental practice (`particle-quiz`, `sentence-building`), `system-fallback` | ≥ 1 первая попытка в выбранном периоде |
| **Review Lapses**            | `state.reviewEvents` & `state.srs` | Оценка `Again (0)` на карточках в стадии `Review` (state = 2)                                                 | Ошибки при первоначальном изучении (state = 0, 1), внутрисессионные доучивания в Relearning                               | ≥ 1 review попытка                     |

## Разделение Retention и Accuracy

- **Observed Retention** измеряется строго по **первой попытке** релевантного review. Повторный успешный ответ в той же сессии после `Again` не повышает retention.
- **Accuracy** на отрезке последних попыток используется как дополнительный параметр при расчёте `mastery depth` и `risk score`, но не подменяет основной показатель FSRS Retention.

## Определение Lapses и Relearning

- **Lapse**: Возникает, когда ранее изученная карточка (находящаяся в состоянии `State.Review` / 2) получает `Again (0)` и переходит в `State.Relearning` (3).
- **Исключения**:
  - Первая ошибка на новой карточке (`State.New` / 0 или `State.Learning` / 1);
  - Повторная ошибка во внутрисессионном доучивании;
  - События, отменённые пользователем через Undo (`undoneAt !== null`).

## Учёт Undo и отменённых событий

`getEffectiveReviewEvents(state, options)` производит строгий отбор:

- Исключает записи с `undoneAt !== null`;
- Убирает дубликаты по `eventId`;
- Учитывает только завершённые и подтверждённые записи;
- При выполнении Undo статистическая модель мгновенно пересчитывается без сохранения вычисленных процентов.

## Локальный учебный день (Day Boundary)

Все группировки по дням используют функцию `getStudyDayKey(timestamp, { dayBoundaryHour })` из `src/local-date.js`.

- По умолчанию учитывается локальный часовой пояс пользователя;
- При наличии сдвига начала учебного дня (например, в 04:00 утра) события, происшедшие до 04:00, автоматически относятся к предыдущему учебному дню.

## Прогноз и его ограничения

- **Прогноз карточек**: График `dueToday`, `dueTomorrow`, `byDay14` и `byWeek12` строится по текущим значениям `due` у всех активных non-suspended FSRS карточек.
- **Прогноз времени**: Для каждого дня длительность оценивается как `число карточек × медианное время ответа`. Используется иерархия медиан:
  1. Пользовательская медиана режима (mode);
  2. Пользовательская медиана навыка (skill);
  3. Глобальная медиана времени ответа;
  4. Запасное значение по умолчанию (8000 мс / 8 с).
- **Ограничение**: "Прогноз основан на текущем расписании карточек. После новых ответов даты могут измениться."
