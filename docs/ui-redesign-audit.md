# KotoKitsu UI redesign audit

This audit is the working contract for applying the supplied KotoKitsu prototype to the existing product. Product behavior remains owned by the current Vanilla JS routes, domain modules, state migrations, IndexedDB repositories, FSRS implementation, and tests. The prototype owns visual direction only.

## Existing product contracts to preserve

- Routes: onboarding, home, course, chapter, SRS, user dictionaries, Sensei, AI story, crossword, word search, library, story, profile, quests, statistics, settings, Developer Mode, word details, and Plan.
- Persistence: current IndexedDB schema, state migrations, FSRS cards/review journal, active `SessionManager` record, Pomodoro state, course-scoped progress, and onboarding draft.
- Learning: canonical daily plan, dynamic course package data, FSRS scheduling, mastery evidence, all seven documented study modes plus reverse choice, relearning, hints, skip/fallback behavior, session batching, and undo where currently available.
- Navigation: browser history/deep links, route render abort signals, stable screen IDs, and mobile five-item tab bar.
- Test selectors: existing `data-testid` attributes remain stable. New visual wrappers must not replace tested controls.
- Offline: no external font or critical asset dependency; mascot and icon assets must ship through the PWA build.

## Shared component map

The existing project remains Vanilla JS. Reuse is implemented through stable semantic classes and current render templates rather than introducing a framework.

| Primitive               | Existing equivalents                                                          | Redesign contract                                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| AppShell                | `#app`, `.screen`, `.screen-scroll`, `.tabbar`                                | Warm canvas, responsive navigation rail, bounded content, safe-area-aware mobile shell.                                   |
| Page header/top bar     | `.app-header`, `.screen-header`, Sensei headers                               | Consistent display/body typography, compact actions, sticky behavior where useful.                                        |
| Buttons                 | `.btn*`, `.btn-primary`, `.btn-secondary`, `.btn-ghost`, danger/icon variants | 44 px targets, orange only for the recommended action, visible hover/focus/pressed/disabled/loading states.               |
| Card/surface            | `.card` and domain-specific panels                                            | Use cards selectively; prefer rhythm/dividers for simple groups.                                                          |
| Status/badge/banner     | badges, tags, plan warnings, storage banners, session banners                 | Shared success/warning/error/info soft surfaces with text/icon cues.                                                      |
| Form controls           | `.form-*`, toggles, checkboxes, radios, selects                               | Unified fields, focus ring, validation, disabled and unsaved states.                                                      |
| Tabs/segmented controls | `.lib-tabs`, Sensei tabs, Plan toggles, shop tabs                             | Ink outline, clear selected state, mobile wrapping/scroll only where necessary.                                           |
| Progress/metrics        | streak/XP, Plan bars, FSRS stats, chapter progress, charts                    | Indigo scaffold, semantic fills, tabular numeric typography, accessible labels.                                           |
| StudySessionShell       | `.flash-wrap` and all card-mode renderers                                     | Shared max width, progress/exit header, Japanese prompt scale, answer/feedback/action region.                             |
| Dialog/bottom sheet     | `.modal-overlay`, `.bottom-sheet`, recovery and Pomodoro panels               | Same radii, overlay, elevation, focus treatment, desktop dialog/mobile sheet behavior.                                    |

| Pomodoro widget         | `ui/pomodoro.js` generated trigger/panel                                      | Tomato trigger with state ring; desktop popover and mobile sheet clear of navigation/safe area.                           |

## Prototype differences retained intentionally

- Product navigation and all current routes remain; prototype labels are not copied mechanically.
- Product data, counts, course/chapter names, dates, and SRS metrics remain dynamic.
- Pomodoro keeps all current settings and lifecycle states instead of the prototype’s simplified timer.
- Existing study modes, minigames, shop, quests, Developer Mode, user dictionaries, Notes, import, backups, and system diagnostics remain available.
- Existing custom themes remain functional, but the default light/dark themes establish the new ink-and-fox hierarchy.
