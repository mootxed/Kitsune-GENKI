# Coding Conventions — Стандарты и Соглашения Кода

Настоящий документ определяет стандарты разработки, соглашения по именованию и архитектурные ограничения в проекте **KotoKitsu**.

---

## 📐 Архитектурные правила

1. **Модульность ES Modules**:
   - Все JS-файлы используют нативный формат ES Modules (`import`/`export`).
   - Не создавайте новые глобальные объекты на `window` (`window.myApp = ...`). Все зависимости должны явно импортироваться.

2. **Чистые функции домена**:
   - Функции в папке `src/` (расчет FSRS, вычисление Mastery, формирование учебного плана) должны быть чистыми (pure functions).
   - Доменная логика не должна взаимодействовать с DOM (никаких `document.querySelector` или `element.innerHTML` внутри `src/`).

3. **Безопасность UI и защита от XSS**:
   - Избегайте использования небезопасного `innerHTML` с пользовательским контентом или внешними строками.
   - Для текстового наполнения используйте `textContent` или предварительно экранирующие хелперы (`src/a11y-helpers.js`).

4. **Формат дат и времени**:
   - Все даты внутри состояния и базы данных хранятся в формате ISO UTC (например, `"2026-07-27T14:30:00.000Z"`).
   - Расчёт локального учебного дня выполняется исключительно через `getLocalStudyDay()` (`src/local-date.js`), чтобы сброс дня происходил предсказуемо.

5. **Обработка ошибок**:
   - Функции работы с хранилищем и сетью должны оборачиваться в `try...catch` с понятным логированием:
     ```javascript
     console.error('[ModuleName] Описание контекста ошибки:', err);
     ```
   - Никогда не проглатывайте ошибки без уведомления или записи в диагностику.

---

## 🏷️ Соглашения об именовании (Naming Conventions)

- **Файлы скриптов**: `kebab-case.js` (например, `session-manager.js`, `vocabulary-unlock-plan.js`).
- **Классы**: `PascalCase` (например, `SessionManager`, `IndexedDBWrapper`).
- **Переменные и функции**: `camelCase` (например, `calculateMastery`, `cardId`).
- **Константы**: `UPPER_SNAKE_CASE` (например, `CURRENT_VERSION`, `STORES`).
- **Учебные карточки**: Идентификаторы карточек создаются строго в формате `${itemId}:${skill}` (например, `genki1_l1_v1:vocabulary-meaning`).

---

## ♿ Требования к доступности (Accessibility / A11y)

- Все интерактивные элементы UI должны поддерживать навигацию с клавиатуры (`Tab`, `Enter`, `Space`, `Escape`).
- Для японского текста на странице обязательно указывать атрибут `lang="ja"`.
- Цветовые индикаторы (правильно/ошибка) обязаны дублироваться иконками или текстом.
